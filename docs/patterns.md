# 工程模式与边界

## 模式 A：路由器

让 Jev 选择队列、工具或处理策略，再由白名单代码执行。候选项要包含 `other` / `unknown`，避免把未知输入硬塞进具体类别。

## 模式 B：低成本筛选器

先对大量短文本做 Noul 或 Choice 筛选，仅把命中或低置信度样本交给昂贵的 LLM。保留抽样复核，以监控漏检。

## 模式 C：LLM 输出评审器

将原始请求、模型输出和规则一起放入 state，使用多个 Noul / Score 问题做独立检查。评审结果只能作为发布门槛或人工辅助，不能替代安全审计。

## 模式 D：人机协同

推荐三段式策略：高置信度自动处理，中间区间人工复核，低置信度升级到更强模型。阈值、超时、重试和降级都应由应用显式控制。

## 生产清单

- 版本化问题定义、选项顺序和 rubric。
- 对 state 做长度、隐私和注入清理。
- 记录 request id、模型别名、耗时、完整分布和最终标签。
- 对类别不平衡、概念漂移和新类别做定期评估。
- 用幂等键保护重试，避免副作用重复执行。
- 设定超时、预算和速率限制；网关参数不要直接套用直连 API。
- 遇到服务不可用时，选择安全默认值或人工队列，而不是静默放行。
