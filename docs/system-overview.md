# Jev 系统说明

## 一句话

Jev 是 TypeSafe AI 的 System One 模型：给它一段 state 和一组答案空间已经确定的问题，它返回机器可以直接消费的 typed decisions 与概率分布。

## 数据流

```text
业务状态 / 检索结果
        ↓
Choice / Score / Noul 问题定义
        ↓
Jev API（并行决策）
        ↓
答案 + 概率 + 置信信号
        ↓
阈值、代码分支、人工复核或更强模型
```

Jev 的价值在于缩小输出空间。传统 LLM 生成字符串，应用要解析、校验并处理格式漂移；Jev 要求应用先声明候选答案，使分支结果更适合类型系统和自动化流程。这并不意味着结果必然正确：模型可能理解错 state，概率也需要在你的数据上校准。

## 三类问题

| 原语 | 输出形状 | 适用例子 | 不适合 |
| --- | --- | --- | --- |
| **Choice** | 从预定义选项中选一个，并返回各选项概率 | 工单路由、意图分类、工具选择 | 需要自由写解释 |
| **Score** | 在有序等级/量表上评分 | 严重度、风险等级、质量分 | 金额、日期、精确数学 |
| **Noul** | 是/否判断的概率 | 是否需要人工、是否满足规则、是否相关 | 需要多步证明的开放问题 |

具体字段和版本请以 [官方开发者文档](https://docs.typesafe.ai/) 为准；社区 SDK 的命名可能不同。

## 与聊天模型怎么配合

- **生成层**：LLM 负责写回复、提取候选、总结长上下文。
- **决策层**：Jev 对生成结果做路由、审核、评分或 guardrail。
- **执行层**：普通代码负责权限、事务、钱和副作用。

一个安全的客服流程是：检索订单 → LLM 生成候选回复 → Jev 判断是否符合退款政策 → 低于阈值进入人工 → 代码执行退款。Jev 的回答不应单独获得退款权限。

## 概率、阈值与校准

将最高概率记为 `p_top`，只有在 `p_top >= threshold` 且输入通过基本校验时才自动分支。阈值不是 Jev 的默认真理，应使用你自己的标注集选择，并报告准确率、覆盖率、拒答率、Brier score 或 ECE。概率分布平坦时，保留原始分布并升级处理；不要只保存 winner。

## 已知边界

- **没有开放式文本输出**：需要句子、代码或解释时调用生成模型。
- **新鲜度由应用负责**：Jev 不会自行查询新闻、网页或数据库。
- **托管与访问**：公开开发资料将 Jev 描述为 API 服务；不要假定存在可下载官方权重或可离线运行的官方二进制。
- **答案空间设计决定上限**：遗漏“其他/未知/无法判断”会把模型强行塞入错误类别。
- **延迟和价格是动态的**：不要把博客中的单次测量写成 SLA。

## 术语表

- **state**：供模型判断的事实、文本或结构化业务上下文。
- **typed question**：带有固定输出形状的问题定义。
- **confidence / probability**：决策信号；具体含义和校准方式以 API 文档为准。
- **System One**：TypeSafe 对“快速、结构化决策模型”这一产品类别的命名，不等于心理学实验中的完整认知理论。
